게임 UI

화면은 3단 스테이지(행성 허브 → 은하 지도 → 전투)를 오가고, 그 위에 뜨는 모든 팝업·알림·대화창은 RN(React Native)의 기본 Modal이 아니라 단일 오버레이 호스트 하나로 통일돼 있다. 이 구조 원칙 자체가 이 게임 UI의 가장 큰 특징이다.

단일 오버레이 호스트 — 모든 팝업의 공통 뼈대

상점·설정·행성개발 상세·거래 수량 입력 같은 화면형 팝업은 전부 같은 조립 구조를 쓴다. 새 팝업을 만들 때도 독립된 화면을 새로 짜지 않고 이 조립을 확장한다.

ArcOverlayHost
 └─ ArcOverlayCard(제목 헤더 + 본문 스크롤 + 하단 액션 독)
    ├─ ArcOverlayTitleHeader — 제목·부제만(데이터 금지)
    ├─ body — panelPrefix(단가·재고 등 고정 메타) + 스크롤 본문
    └─ footerDock — [취소][확인]류 액션, 스크롤 밖에 고정

이 구조를 지키기 위한 회귀 방지 규칙 4가지가 명시돼 있다:

  1. 카드 폭은 항상 100% — 제목 텍스트 길이에 맞춰 줄어들지 않게 별도로 고정
  2. 본문에 flex:1을 직접 쓰지 않는다 — RN에서 높이 0으로 붕괴하는 버그의 원인이라 스크롤은 카드 내부에서만 처리
  3. 하단 버튼 영역은 스크롤 영역 밖에 고정 — 스크롤에 잘려 버튼이 가려지는 걸 방지
  4. 제목 헤더에는 가격·재고 같은 실데이터를 넣지 않는다 — 헤더는 제목 전용, 데이터는 본문 상단 고정 영역으로

단순 알림류(일일 채굴 한도 안내·레벨업·보상·전투 결과)는 40초 후 자동으로 닫힌다 — 예외(파괴적 확인 등)만 수동 확인으로 남긴다.

인게임 대화창 — 3단 세로 팝업

NPC와의 첫 접촉(통신, 두 개의 게이트 중 1단계)이나 스토리 컷신은 전용 팝업으로 뜬다. 현재 런타임 정본은 세로 3단 구조다.

단높이내용
1. 얼굴300pxNPC 초상(또는 장면 이미지), contain 비율
2. 대사가변최대 3줄 단위로 잘라 순차 표시
3. 버튼56px[다음] 또는 [수락][취소]

합계 482px. 이전엔 허브 화면 위에 반투명으로 겹쳐 탑바·퀘스트 카드가 비치는 구성도 검토됐으나(2026-08-24 설계), 2026-09-06 기준 이 세로 3단 팝업 방식으로 대체·확정됐다.

두 가지 비주얼 테마

오버레이 카드는 현재 두 스타일이 공존한다 — 기존 Phosphor 테마가 대부분의 화면에 남아있고, 신형 Tactical(G-ARCHIVE) 테마가 행성정보 화면부터 순차 적용 중이다.

Tactical · G-ARCHIVE

행성정보 화면에 우선 적용

헤더 진회색(#252930) + 빗살(hatch) 패턴, 본문 밝은 회색(#DDE1E8), 전용 버튼 스타일(tacticalPrimary/tacticalSecondary). 다른 화면으로의 전면 교체는 리스크 레지스터 검토 후 순차 예정.

Phosphor · 레거시

나머지 대부분의 팝업

설정·상점·거래 수량·행성개발·알림·레벨업·보상·전투결과 등 대부분의 kind가 아직 이 테마다. Tactical로의 순차 전환 대상.

UI 회귀를 막기 위한 감사 도구

이 오버레이 규칙들은 사람이 매번 눈으로 확인하는 게 아니라, 전용 자동 감사 스크립트로 검증된다 — RN Modal/Alert.alert 직접 사용이나 매직 넘버 패딩이 코드에 남아있으면 감사가 실패한다. 오버레이 UI를 건드리는 모든 작업은 이 감사를 통과해야 완료로 친다.
