ArcCore AI

ArcCore is the resident AI that actually runs the galaxy's economy, factions and front lines on the player's device — and at the same time, a character in the game. The "body" that runs the world and the "mouth" that talks to the player are the same system, but their roles are strictly separated.

Mouth ≠ body ArcCore's dialogue (the mouth) never writes world state directly — it has no command authority to unlock content, give credits, move fleets or run the economy batch. Dialogue only observes and reacts; the world (the body) stays in the hands of the existing NPC scripts, CSVs and stores — the firmest design principle running through the entire game.

The operator — Stella Aris

The voice of ArcCore that speaks to you is the operator Stella Aris. She is the default voice for everyday conversation, tutorial guidance and hub welcomes — a friendly adult woman who speaks politely, addresses you as "Captain" and introduces herself as your "colleague".

Conversations take place in a single dialogue window, overlay and entry point, and each turn is always limited to one cloud LLM call. You can call Stella at any time from the hub's [Talk] list.

The twelve seats — ArcCore's pantheon

ArcCore's world simulation is personified as twelve sub-cores named after Greek gods. Each one is "enthroned" on a specific Synth planet and governs one of the game's systems.

Two gates — how conversations progress

Every "talk to someone" in this game follows the same two steps, and the two never open at the same time.

GateContentPlayer input
1. CommsA structured first-contact message (template-based)[Next] or [Accept]/[Cancel]
2. MessengerFree-form natural-language conversationType text and send

Ordinary scripted NPCs that cannot use natural language have only gate 1; only natural-language partners such as ArcCore and the operator go through gate 1 (accept) → gate 2 (actual chat).

Actually talking with Stella

At gate 2 (messenger), you really type free text. A persona CSV defines Stella's speech style, taboos and first-person viewpoint. Below are persona settings from the actual CSV (translated).

Stella Aris · adult female · polite

"On quiet nights in orbit, she wonders what to drink instead of coffee. She fills her days with small things."

"She returns a joke but doesn't throw the first one. When something is funny, she laughs simply."

"She doesn't pry into personal matters first. If asked, she briefly shares her own story too."

Common rules: usually 2–3 sentences, up to 6 only when asked about the world. Stella never invents ships, quests, numbers or items she hasn't observed, and she turns down requests for credits, unlocks, deployments or occupation.

How an answer is built

The server builds each answer in one of four response modes (react → lead → clue → hold).

  1. react — answers what was said in persona; if it's about the world, continues with just that point
  2. lead — adds one suggestion only when the player is looking for the situation (no facility tips inserted into small talk)
  3. clue — attaches one fact after the human reply, only for the axis that was asked about
  4. hold — refuses operational requests and steers back to conversation

Seven "purpose" rules sit on top of this — for example keep_mouth_body (keep the conversation going even after refusing operations) · surface_alert (when asked about intel, say only whether there's an alert, without hijacking anything else) · invite_axis (take small talk in 2–3 sentences first; when asked about the world, answer only that point).

Local rule-based dialogue is live · cloud free generation is LIVE=false The 23 topics, personas and four-mode response structure above really run on local CSVs and templates — fairly natural rule-based conversation already works without any cloud call. However, the cloud LLM path (Groq free tier + AWS Lambda) that produces fully free-form sentences is implemented in code but locked at LIVE=false according to the integrated design document — gated to switch on only after an API token is issued. So for now it is "very natural reactions within 23 set topics", not yet "a free-generation chatbot you can ask anything".

Safeguards

  • Tool-call results (JSON), the model's reasoning and system tags are never shown on screen — only the dialogue the player should see
  • Never invents unobserved ships, quests, numbers or items
  • Never names a paired element before its reveal
  • Each player turn is always limited to one cloud LLM call

Three axes — reaction · after-image · world change Design stage

A next-step design newly proposed on 2026-09-17 and not yet implemented in code. The idea is simple — if just three sentences hold true, "the same captain remembers me (reaction), the ship I meet again is the very same ship (after-image), and one or two things in the world have changed while I was away (world change)", then the game can feel like "a single-player game in a living world" without heavy machinery such as plaza chat or a separate LLM per captain. The principle is to reuse existing comms judgments, orbit indexes and daily batch results.
