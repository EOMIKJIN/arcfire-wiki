Game UI

The screen moves between three stages (planet hub → galaxy map → combat), and every popup, alert and dialogue window on top of them is unified under one single overlay host rather than React Native's default Modal. That structural principle is itself the defining trait of this game's UI.

The single overlay host — a shared skeleton for every popup

Screen-style popups such as the shop, settings, planet development details and trade quantity input all use the same assembly. New popups extend this assembly instead of building a standalone screen.

ArcOverlayHost
 └─ ArcOverlayCard (title header + scrolling body + bottom action dock)
    ├─ ArcOverlayTitleHeader — title and subtitle only (no data)
    ├─ body — panelPrefix (fixed meta such as unit price and stock) + scrolling body
    └─ footerDock — [Cancel]/[Confirm]-style actions, fixed outside the scroll

Four anti-regression rules are spelled out to protect this structure:

  1. Card width is always 100% — fixed separately so it doesn't shrink to fit the title text
  2. Never put flex:1 directly on the body — it causes a collapse-to-zero-height bug in RN, so scrolling is handled only inside the card
  3. The bottom button area is fixed outside the scroll area — so buttons never get cut off by scrolling
  4. No real data such as price or stock in the title header — the header is for the title only; data goes in the fixed area at the top of the body

Simple notices (daily mining limit, level-up, rewards, combat results) close automatically after 40 seconds — only exceptions such as destructive confirmations remain manual.

In-game dialogue — a three-tier vertical popup

First contact with an NPC (comms, step 1 of the two gates) and story cutscenes appear in a dedicated popup. The current runtime standard is a three-tier vertical layout.

TierHeightContent
1. Face300pxNPC portrait (or scene image), contain ratio
2. LinesVariableSplit into chunks of up to 3 lines and shown in sequence
3. Buttons56px[Next] or [Accept][Cancel]

482px in total. A semi-transparent layout overlaid on the hub, with the top bar and quest cards showing through, was also considered earlier (2026-08-24 design), but as of 2026-09-06 it was replaced by and finalized as this three-tier vertical popup.

Two visual themes

Two overlay card styles currently coexist — the older Phosphor theme remains on most screens, while the new Tactical (G-ARCHIVE) theme is being rolled out step by step, starting with the planet info screen.

Tactical · G-ARCHIVE

Applied first to the planet info screen

Dark gray header (#252930) with a hatch pattern, light gray body (#DDE1E8) and dedicated button styles (tacticalPrimary/tacticalSecondary). A full switch on other screens is planned step by step after a risk register review.

Phosphor · legacy

Most other popups

Settings, shop, trade quantity, planet development, alerts, level-up, rewards, combat results and most other kinds still use this theme. They are scheduled to move to Tactical over time.

The three-stage structure

StageScreenTransition rule
STAGE 1Planet hubTransitions always use replace() — navigate(), which keeps the previous stage's resources alive for the back button, is forbidden. Releasing the previous stage's resources (especially Skia render resources) on transition is mandatory.
STAGE 2Galaxy map
STAGE 3Combat

Audit tooling against UI regressions

These overlay rules are not checked by eye every time; they are verified by a dedicated automated audit script — if direct use of RN Modal/Alert.alert or magic-number padding remains in the code, the audit fails. Any work touching the overlay UI counts as done only after passing this audit.
